One fix
  Makefile.mac adds -DNO_THREAD_LOCAL, which selects a macro in random.h
  with one closing parenthesis too many; it does not compile ("extraneous
  ')' before ';'" in random.c). Fixed upstream after the release, in
  commit 6f27988287160baa199b58a14eac45b58fc035e9 ("random: fix
  pcg32_set_state macro typo", 17 April 2026); the same change was made
  here:
  -#define pcg32_set_state(pt)	pthread_setspecific(random_state_key, (pt)))
  +#define pcg32_set_state(pt)	pthread_setspecific(random_state_key, (pt))

Checks against a miscompile (GNU Go 3.8 is miscompiled by Apple clang)
  - Unit tests. "make test" stops early on macOS (its run_tests needs
    tac, and its GTP check a GNU grep pattern), so the test files were
    run as run_tests does: pachi --kgs -d2 -u t-unit/FILE.t, for every
    t-unit/*.t not marked "auto-run off". Both builds pass every
    mandatory test, 649 in 16 files (atari 29, bent4 7, can_countercap 8,
    false_eye_seki 3, is_selfatari_stress_test 1, ladder 24, ladder_any
    25, moggy 4, pass_is_safe 26, seki 157, selfatari 320,
    selfatari_stats 1, two_eyes 26, useful_ladder 7, wouldbe_ladder 5,
    wouldbe_ladder_any 6). The other two files (dcnn_blunder,
    first_line_blunder) use commands that exist only in DCNN builds. The
    optional tests, known failures, fail alike in both (ladder 0/2,
    selfatari 0/4, two_eyes 0/1, useful_ladder 0/1, pass_is_safe 0 or 1
    of 3 from run to run: its playouts are randomly seeded).
  - Regression outputs, with a BOARD_TESTS=1 build of each compiler
    (linked against Homebrew's OpenSSL): the board-logic output
    (t-unit/regtest.gtp) and the spatial-pattern output
    (t-unit/spatial.gtp) match the references (regtest.ref.bz2,
    spatial.ref.bz2) byte for byte with both compilers. The seeded
    playout output (tunit moggy_regtest) matches neither build's
    reference, moggy.ref.bz2, last regenerated on 8 November 2025 before
    the release's playout changes (the moggy and bent-four commits of
    January and February 2026), but is byte-identical between the clang
    and the GCC build.
  - Games. Pachi's fixed-playout search stops on a wall-clock check (see
    pachi-match.sh), so seeded games are not reproducible move for move
    and cannot be compared between builds. Instead the GCC build played
    the clang build 100 games at -t =4000 (matches/pachigcc-p4k): 55/100
    for GCC, +35 Elo (95% interval -33 to +103), against 58/100 in the
    same match of the clang build against itself (matches/pachi4k-p4k).
  - No crash or assertion in any game of the matches in matches/, all
    with Pachi's default stop check.

One configuration that does crash
  Pachi's option reportfreq=0.005s makes it check its playout count every
  5 ms instead of every 50 ms, which would make -t =N nearly exact; it
  was tried first and dropped after one game against GNU Go stopped on
    Assertion failed: (ownermap->playouts >= GJ_MINGAMES), function
    uct_pass_is_safe_, file uct.c, line 174.
  Each search first runs 500 ownership playouts (about 20 ms here) in the
  search thread; the default interval (100 ms before the first check of
  a process, 50 ms after) is longer, while a 5 ms one lets the main
  thread ask whether a pass is safe before they are done. A race in
  Pachi exposed by the setting, not a miscompile; the matches use the
  default interval.
