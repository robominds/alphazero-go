# 16-bit CUDA inference (backend = cuda16) on the RTX 4070 Ti SUPER (2026-10-24)
#
# Design: docs/superpowers/specs/2026-10-24-cuda-fp16-design.md. Branch
# cuda-fp16. Machine: the PC of docs/results/cuda-bench.txt (AMD Ryzen 7
# 7700X, RTX 4070 Ti SUPER sm_89, WSL2 Ubuntu 24.04, CUDA 12.8, driver API
# 13.3). Release builds, AZ_CUDA_ARCHITECTURES 89-real.
#
# The PC was the live 19x19 run's largest engine (pc/cuda, a selfplay
# --stream process with 128 games in flight) during every measurement
# here unless a section says otherwise: its GPU was at 100% before we
# started. Rates measured beside it are therefore shared-GPU rates. The
# comparisons that matter (cuda16 against cuda, fp16 against bf16) were
# measured back to back in the same conditions, so their ratios hold; the
# absolute rates are lower bounds.
#
# ======================================================================
# Summary
# ======================================================================
#
# 1. Speed. cuda16 is 4.3x cuda on 19x19 10x128 and 4.6x on 13x13 6x96 at
#    batch 256 (raw two-slot passes, shared GPU, same conditions), and the hub keeps
#    the ratio. Per trunk convolution the tensor-core kernel is 4.3-4.7x
#    the fp32 fused kernel at batch 256. fp16 and bf16 run at the same
#    speed (fp32 accumulation runs at one rate on Ada).
#    On the idle GPU (the live run's training phase, 20:03-20:05), raw
#    two-slot passes at batch 256: 19x19 10x128 27,726 evals/s against
#    cuda's 6,488 (4.3x); 13x13 6x96 125,587 against 29,998 (4.2x). The
#    hub at 128-256 threads: 27,500 and 124,700 (cuda 6,470 and 29,660).
#    One 19x19 trunk convolution runs at 64.8 TFLOP/s, about 74% of the
#    GPU's ~88 TFLOP/s for fp16 with fp32 accumulation, against 14.5 for
#    the fp32 kernel. A real 19x19 slice ran at 27.2k evals/s.
#
# 2. Accuracy, on real positions of real checkpoints against the network
#    in double precision:
#
#                        positions  logits rel  value max  argmax   KL mean
#    13x13 gen 100 fp16       1024     2.1e-3     2.7e-3   100.00%  8.8e-7
#    13x13 gen 100 bf16       1024     1.4e-2     2.8e-2    99.32%  5.4e-5
#    19x19 gen 7   fp16        600     2.6e-3     3.0e-3   100.00%  2.9e-8
#    19x19 gen 7   bf16        600     1.8e-2     2.9e-2    99.67%  1.7e-6
#    (cuda and blas, fp32: <= 3.1e-6 and 4.2e-6, argmax 100%)
#
#    "logits rel" is the worst position's max |d| / max |ref|; value
#    signs agreed in every position with |ref| > 0.05 for all engines.
#    fp16 is 7-10x closer than bf16, and its range is ample: the largest
#    trunk activation was 20.5 (13x13) and 28.8 (19x19) against 65,504.
#    So the backend ships fp16. The tier (the design's "Accuracy"): logits
#    5e-3, value and ownership 1e-2, about twice the measurements.
#
# 3. Batch independence. The convolution is bitwise the same for a
#    position alone and at the first, a middle and the last place of
#    batches of 8, 144 and 256, among random companions, for every channel
#    tile and on repeat (half_bench det; test_cuda16), as is the whole pass
#    (test_cuda16: batches of 1 to 256, permuted, repeated, a second
#    upload), the runner, the hub under chaos, self-play slices and arena
#    waves for any workers and batch cap, and a run across resume.
#
# 4. Strength. The 13x13 run's generation 100 playing itself at 800
#    simulations, one side on cuda16, the other on cuda, colours
#    alternating: cuda16 scored 157 of 288 = 54.5% +- 5.8% (95%), i.e.
#    +31 +- 40 Elo. 50% is inside the interval: no loss of strength shows
#    at this sample size (it would reveal a deficit of about 40 Elo).
#
# 5. The CPU side. A real self-play slice (train with selfplay_engines =
#    local/cuda16:1, the 19x19 run's settings and generation 7, 128 games
#    in flight, 800 simulations, capped at 12 plies) ran at 27.2k evals/s
#    on the idle GPU with the whole process at 1.64 cores (44.3 s user +
#    16.6 s system over 37 s, startup included) of the PC's 16 threads,
#    and at 10.0k evals/s and 0.66 of a core on the shared GPU. The tree
#    search feeds the faster GPU with most of the CPU to spare; the hub's
#    passes stay full (mean 248 of 256 at 128 threads).
#
# 6. Nothing else changed: the cuda backend's kernel hash is 176be8be on
#    main and on the branch (the live run's fingerprint); the identity runs
#    of main against the branch (naive and BLAS builds) are byte-identical
#    (below); every ctest passes on the PC's CUDA build (test_metal
#    Skipped) and the Studio's BLAS and Metal builds (the CUDA tests
#    Skipped).
#
